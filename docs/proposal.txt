1. TITLE
--------------------------------------------------------------------------------
HANOI GUIDE – An Interactive Multilingual Travel Guide Website for Hanoi
(Front-end web project using HTML, CSS, JavaScript with public API integration
and an AI chatbot)

Project type : Design a simple website using HTML, CSS, JS – Travel guide
Team size    : 4 members
Duration     : 8 weeks
Repository   : GitHub (public), deployed with GitHub Pages
Chatbot proxy: Cloudflare Workers (free tier)


2. OBJECTIVES
--------------------------------------------------------------------------------
General objective
  Build a responsive, multilingual travel-guide website that helps domestic and
  foreign tourists discover Hanoi's history, attractions and cuisine, plan a
  trip, and get instant answers from an AI assistant.

Specific objectives
  O1. Present Hanoi's history, tourist attractions and food & drink in a
      structured, visually attractive way (Vietnamese / English / Chinese).
  O2. Integrate public APIs so the content is live and interactive instead of
      static text: weather, air quality, maps, exchange rate, Wikipedia
      summaries.
  O3. Let users build and save a personal itinerary, and open places directly
      in Google Maps, GrabFood and ShopeeFood from their phone.
  O4. Provide an AI chatbot (LLM through a secure server-side proxy) that
      answers travel questions in the user's language and can interact with
      the website (show place cards, add items to the itinerary).
  O5. Apply good front-end engineering practice: data-driven rendering from
      JSON, modular JavaScript, i18n, responsive mobile-first layout, Git
      workflow, and deployment to a public URL.

Learning objectives
  - Practise semantic HTML5, modern CSS (Flexbox/Grid, responsive design,
    dark mode) and vanilla ES modules without a framework.
  - Learn to consume REST APIs with fetch, handle async errors and rate limits.
  - Understand why API keys must not be exposed in client code and how a
    serverless proxy solves this.
  - Practise teamwork with Git branches, pull requests and issue tracking.


3. SCOPE
--------------------------------------------------------------------------------
3.1 In scope
  Content modules (all in 3 languages: vi / en / zh-CN)
    - Home page: hero banner, live weather + AQI widget, quick search,
      highlights of the month.
    - History: interactive timeline (Thang Long 1010 -> Hanoi today),
      "then & now" photo comparison, Wikipedia summaries.
    - Attractions: filterable card grid (historic sites, Old Quarter, museums,
      lakes & parks, markets, cafés), detail page with hours, ticket price,
      suggested visit duration, tips, gallery, embedded map, "Buy ticket /
      Book tour" link where available (official site, Klook, GetYourGuide),
      "Add to itinerary" and "Favourite".
    - Food & Drink: dishes and recommended restaurants with price range,
      opening hours, and deep-link buttons: Google Maps (directions),
      GrabFood, ShopeeFood, Apple Maps.
    - Itinerary: 3-4 sample itineraries (1/2/3 days), drag-and-drop builder,
      automatic cost + distance + total time estimate (visit duration +
      travel time) with an "over-packed day" warning, saved in localStorage,
      export to PDF, "Open route in Google Maps".
    - Interactive map (Leaflet + OpenStreetMap) with category markers and
      "near me" sorting via browser Geolocation.
    - Accommodation: curated hotels/hostels/homestays by area and budget
      (Old Quarter, Hoan Kiem, West Lake, near Noi Bai), with price range,
      star rating, distance to centre, and "Book on" buttons that deep-link
      to Booking.com, Agoda, Traveloka and Google Hotels with the selected
      check-in / check-out dates and number of guests pre-filled. A date
      picker on the page passes the dates into the links.
    - Transport & Getting around: airport-to-city options, ride-hailing
      buttons (Grab, Xanh SM, Be), public bus/metro (Cat Linh–Ha Dong,
      Nhon–Hanoi station lines) with route info, motorbike/bike rental tips,
      walking-distance chart between attractions.
    - Events & Festivals: month-by-month calendar (Tet, Mid-Autumn, Old
      Quarter weekend walking street, Hanoi Pride-free cultural events,
      concerts), filter by the user's travel dates.
    - Shopping & Nightlife: markets (Dong Xuan, night market), craft
      villages (Bat Trang, Van Phuc), souvenirs, bia hoi corner, rooftop bars,
      water puppet show with ticket-booking link.
    - Nearby day trips: Ninh Binh, Ha Long, Duong Lam, Ba Vi – distance,
      travel time, suggested tour links.
    - Practical guide: budget calculator with live exchange rate, SIM/eSIM
      & Wi-Fi, visa summary with official link, emergency numbers (113/114/115),
      tourist police, hospitals & 24h pharmacies, embassies, tipping &
      bargaining etiquette, temple dress code, best time to visit, packing
      checklist.
    - Common scams & safety: illustrated list of frequent tourist scams in
      Hanoi (unmetered taxis, cyclo overcharging, shoe-shine, money changers,
      look-alike 20k/500k notes, "the temple is closed" touts) with how to
      avoid each; recommended taxi/ride apps and official exchange points.
    - Reviews & Ratings: users rate places/foods (1–5 stars + comment),
      stored in localStorage (optional Firebase Realtime DB for shared
      reviews).
    - Photo Gallery: seasonal albums with lightbox; user can upload photos
      to a "My trip" album stored locally.
    - About / Contact page with team info and feedback form.

  Interaction & integration
    - "My Trip" context: the user enters travel dates, group size, budget
      level and interests once (stored in localStorage); every module reads
      it – events and weather forecast filtered to those dates, hotel links
      pre-filled, itinerary suggestions and chatbot answers personalised.
    - Multilingual UI (JSON dictionaries + data-i18n attributes), language
      auto-detected from browser, remembered in localStorage.
    - AI chatbot widget: streaming answers, quick-reply chips, multilingual,
      grounded in the site's own JSON data and live weather; returns
      structured actions (show_places, add_to_itinerary) handled by the
      front-end.
    - Serverless proxy (Cloudflare Worker) that hides the LLM API key,
      enforces CORS whitelist and per-IP rate limiting.
    - Dark mode, favourites, search with autocomplete, trip checklist.
    - Share itinerary: encode the plan into a URL (base64) + QR code so
      friends can open it; "Add to Google Calendar" link per day.
    - Weather-aware suggestions: rainy day -> museums/cafés, hot day ->
      lakes/evening walking street; AQI warning banner when unhealthy.
    - PWA: installable on phone, offline caching of pages and JSON data.
    - Read-aloud (Web Speech API) for place descriptions in 3 languages.
    - "What kind of traveller are you?" quiz that recommends an itinerary.
    - Phrasebook: ~60 essential Vietnamese phrases (greetings, ordering food,
      bargaining, taxi, emergency) with EN/ZH meaning, pronunciation guide
      and text-to-speech playback.
    - Dietary filters on Food page: vegetarian, halal, no-pork, not spicy,
      allergen notes.
    - "Open now" badge computed from opening hours in Hanoi time (UTC+7),
      plus Tet / public-holiday closure notes.
    - Hanoi local clock, sunrise/sunset time (Open-Meteo) for photo spots.
    - Contact form via a static-site form service (Formspree / Web3Forms).
    - Custom 404 page, loading skeletons, empty states, price disclaimer,
      OpenStreetMap attribution, clear permission prompt before geolocation.
    - SEO & sharing: meta description, Open Graph / Twitter cards per page,
      sitemap.xml, hreflang tags for vi/en/zh.

  APIs used (all free tier)
    - Open-Meteo (weather, air quality) – no key
    - Leaflet + OpenStreetMap tiles, Nominatim geocoding – no key
    - Wikipedia REST API (vi/en/zh summaries) – no key
    - open.er-api.com (exchange rate VND/USD/CNY) – no key
    - Google Maps / Apple Maps URL schemes, GrabFood & ShopeeFood web links
    - Hotel deep links: Booking.com, Agoda, Traveloka, Google Hotels
      (URL parameters for dates/guests; optional Booking.com Affiliate or
      Travelpayouts API for live prices if approved)
    - Ride-hailing links: Grab (grab://), Xanh SM, Be
    - Google Calendar "add event" URL, QR code library (qrcode.js)
    - Google Gemini API or Anthropic Claude API (via Worker) – key kept
      server-side
    - Optional: Firebase Realtime Database (shared reviews), Unsplash/Pexels
      API (photos)
    - Browser APIs: Geolocation, localStorage, Web Speech (read aloud),
      Service Worker (PWA offline), Web Share API

3.2 Out of scope
  - User accounts/login and server-side database (except optional Firebase
    for reviews).
  - Processing bookings or payments ourselves: hotels, tours, food orders and
    rides are handed off to the partner apps/websites via deep links; the
    site does not hold booking data or money.
  - Native mobile app; the site is a responsive PWA.
  - Content for provinces outside Hanoi.
  - Guaranteed 100% accuracy of third-party data (prices/hours are
    reference values, with a disclaimer).

3.3 Constraints & assumptions
  - Front-end must be pure HTML/CSS/JS (no React/Vue build step), hosted as
    a static site.
  - Only free-tier APIs; total cost = 0 VND.
  - Chinese content is Simplified Chinese (zh-CN).
  - Target browsers: latest Chrome, Edge, Firefox, Safari (desktop + mobile).

4.2 Non-functional requirements
  N01 Mobile-first responsive layout (320 px – 1920 px), no horizontal scroll.
  N02 Lighthouse: Performance >= 85, Accessibility >= 90, Best Practices >= 90.
  N03 All external calls handle failure (fallback text, retry or cached data).
  N04 No API key committed to the repository; secrets stored as Worker
      secrets.
  N05 Code organised in ES modules (api.js, i18n.js, render.js, storage.js,
      map.js, chatbot.js), consistent naming, comments in English.
  N06 Semantic HTML, alt text for images, keyboard-navigable chatbot.

4.5 Success criteria
  S1  All MVP requirements F01–F13 work on the live URL with no console
      errors on desktop and mobile.
  S2  Every page fully available in vi, en and zh with no untranslated
      strings (checked by an automated i18n key-coverage script).
  S3  Chatbot answers >= 90 % of a 30-question test set correctly (grounded
      in site data) in each of the 3 languages, average first token < 3 s.
  S4  Lighthouse scores meet N02 on the Home, Attractions and Food pages.
  S5  All deep links (Maps, GrabFood, ShopeeFood, Booking, Agoda, Traveloka)
      open the correct target on a real Android and iOS device.
  S6  Zero secrets in the repository (checked with git-secrets / manual
      review); Worker rejects requests from non-whitelisted origins.
  S7  Report, slides and demo delivered on time; each member can explain and
      demo his/her own module.

4.6 Risks & mitigation
  R1  Third-party API down or rate-limited (Open-Meteo, Wikipedia, exchange
      rate) -> cache last response in localStorage, show fallback text,
      never block page render.
  R2  LLM API quota exceeded or key leaked -> key stored only as Worker
      secret; per-IP rate limit; provider switch (Gemini <-> Claude);
      chatbot falls back to a rule-based FAQ mode when the proxy returns
      an error.
  R3  GrabFood / ShopeeFood / booking-site URL formats change -> links are
      data-driven in JSON, one place to update; each button has a generic
      search-page fallback.
  R4  Chinese translation quality -> machine-translate first, then review
      by a Chinese-speaking classmate or lecturer; keep sentences short.
  R5  Content accuracy (prices, hours) -> record source and date for every
      entry, show "last updated" and a disclaimer.
  R6  Scope creep (24 features) -> strict MVP line (F01–F13); weekly review
      moves unfinished optional features to future work.
  R7  Member unavailable / uneven contribution -> shared task board, weekly
      commits required, pair backup for each module (1<->4, 2<->3).
  R8  Image copyright -> use own photos, Wikimedia Commons (CC) or Unsplash
      / Pexels with attribution list in the footer and report.
  R9  Browser differences (Safari Web Speech, iOS deep links) -> feature
      detection and graceful degradation; test on real devices early
      (week 3).
